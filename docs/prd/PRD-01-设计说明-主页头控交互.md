> - 依据：PRD-01 V1.0-r3
> - **交互 v1.1（2026-09-01）**：Rokid 官方确认触控板与物理按键的「长按」均无支持计划（GlobalHook 单次物理按压恒等于一对瞬时按下/抬起脉冲，真机探针实测 24ms 内完成）。原「长按 ≥500ms」语义全部改由**双击触控板**承担。
> - **交互 v1.2（2026-09-01）**：真机实测 `onKeyUp` 的 `preventDefault()` **无法拦截宿主「双击触控板 = 退出程序」默认行为**，双击语义整体弃用。全部交互收敛为**单击**：单击进入选择态 / 唤出游戏内菜单；点亮态单击确认；未点亮单击取消（游戏菜单内则继续游戏）。原 A2 提示态取消（提示文案并入 A3 选择态底部常驻行，画布 A2 屏待下轮修订移除）；设置页返回主页改为列表末行「返回主页」；战绩页单击返回主页。
> - **交互 v1.3（2026-09-01）**：待机态**真·停采**——IMU 传感器仅在选择态（及其后续）运行，待机 / 回待机一律 `stop()`（转头无效果 + 关闭监听，降功耗发热）。单击待机 → `start()` + 以当前姿态重立会话基准 + 进入选择态。
> - **交互 v1.4（2026-09-01）**：**IMU 异常不再劫持单击**——待机单击一律进入选择态（Craft 模拟器无 `AbsoluteOrientationSensor` 也能走查 UI）；IMU 不可用时头控输入恒为 0，选择态提示行切换为「IMU 不可用 · 双击触控板退出」（宿主双击=退出程序，即逃生口）。右上角 HUD 由「IMU 健康显示」改为**页面状态显示**：`状态：待机中`（空心点，停采）/ `状态：选择中` / `状态：已选中`（覆盖跳转期与退出确认期）。原 v1.3 的 1.2s 预热宽限与「硬失败直达退出浮层」逻辑一并移除（TOUCH.warmup 删除）。
> - **交互 v1.5（2026-09-01）**：①**按压消抖**——真机实测 GlobalHook 一次物理按压产生多对 D/U 脉冲（短按=单击后状态被二次单击打回、长按=停在选择态），keyUp 派发后进入 150ms 消抖窗口（TOUCH.tapDebounce），一次物理按压恒等于一次语义；②**轴通道互换**——设备四元数轴系与标准假设差 90°（头部上下↔画面左右、左右↔上下），`quatToAngles` 增加 `SWAP_AXES` 开关（已开启）交换 yaw/pitch 输出通道，yaw 恒为水平、pitch 恒为垂直。
> - **交互 v1.6（2026-09-01）**：消抖窗口 150→250ms（真机单击进选择态仍不稳定时的保守调参）。
> - **交互 v1.7（2026-09-01）**：**双键码序列定案**——主页屏幕取证（底部事件流）确认一次物理按压 = `D:GlobalHook U:GlobalHook(+6ms)` → `约 483ms 后 D:Enter U:Enter(+36ms)`。判定器新增 **Enter 抑制**：GlobalHook 抬起后 600ms 内的 Enter 对整体吞掉（同一次按压的语义通道），根治「单击进选择态被二次单击打回」；消抖窗口回调 150ms（250ms 会吞 200ms 级快速连点）；纯 Enter 物理键不受影响。模拟验证 7 场景全部符合预期。

## 01 · 设计令牌：单绿视觉规范

单绿色单色透明显示：**纯黑即透出现实**，一切「变暗」只能通过降低元素自身 alpha 实现，**禁止黑色遮罩层**。以下令牌为全部界面唯一取值来源。

### 亮度阶梯（6 级）

| 等级 | 色值 | 用途 |
|---|---|---|
| 100% | `#40FF5E` | 光标本体 / 吸附图标 / 关键数值 / 爆炸 |
| 72% | alpha 0.72 | 主可读文本 / 激活结构线 / 实体描边 |
| 48% | alpha 0.48 | 次要文本 / 常规交互边界 / 未吸附实体 |
| 24% | alpha 0.24 | 分隔线 / 引导线 / 待机态环形入口常态 |
| 12% | alpha 0.12 | 局部分组底纹（最大正常面积填充） |
| 6% | alpha 0.06 | 极弱底纹 / 远景分组 / 选择态导向线 |

### 字号阶梯（官方 6 级）

- 页面标题 22 / 500
- 区块标题 16 / 500
- 正文 14 / 400
- 密排文本 12 / 400
- 标签 11 / 500
- 数据值 monospace 13

### 文字定位规范（Ardot SVG 文字渲染三定律）

> 画布（Ardot）使用 SVG 描述文字，但其解析器对 `<text>` 元素的行为与标准 SVG 不一致。下方三条为本工程实测标定的硬规则，**所有画布设计稿须按此编写 SVG 文字节点**，否则必然出现"文字相对背景框错位"的视觉缺陷。

| # | 定律 | 实测依据 | 设计稿中的应对 |
|---|---|---|---|
| ① | `text-anchor` 属性被**完全忽略** —— 无论 `start` / `middle` / `end`，文字一律以 `x` 值为**左边缘**排布 | 同一文本分别写 `anchor="middle"` 与 `anchor="start"`，像素包围盒完全一致；x 写 80 与写 20 输出位置仅差 60 | 居中须**预计算文本宽度**，用 `x = cx - width/2` 反推左起点 |
| ② | `y` 值是**基线（baseline）**而非顶边 | 16/500 文字 "即将退出应用"，y=58，墨迹 y[44..58]，顶 y = 58 - (size-1) | 垂直居中须 `y = cy + (size-1)/2`（CJK），或 `y = cy + 0.73×size/2`（纯拉丁/数字） |
| ③ | `<text>` 节点被 Ardot 解析为**原生 TEXT 节点**（非 vector），其 `node.y = baseline − size`、`node.height = lineHeight` | `batch_read` 可见节点属性；`batch_edit` 可直接 `U(id, {x, y})` 精确微调文字位置 | 后续微调不必重画整屏，直接用 `U(textNodeId, {x, y})` 即可；微调后再用像素探针回归 |

|---|---|---|
| 摇头晃脑 | 12 / 500 | 48 |

### 合规红线（官方禁止项）

1. 禁止黑色遮罩层压暗内容 —— 黑色即透明地板，遮罩在透明屏上无效
2. 禁止大面积 ≥ 24% 实色填充；分组底纹上限 12%
3. 禁止 emoji、装饰性 glow 与同屏多路持续呼吸动画
4. 禁用 `createPattern`；`drawImage` 仅接受另一 Canvas 实例为源
5. 触控板系统默认行为以宿主为准：**「双击触控板 = 退出程序」实测不可拦截（v1.2 实机结论）**，应用语义不得依赖任何双击手势；单击类默认行为仍应在 `onKeyUp` 尽力 `preventDefault`（尽力而为，非语义前提）
6. **滑动 = 方向键（v1.14 定案）**：触控板前/后滑动在 AIUI 框架层表现为方向键序列（`ArrowUp` / `ArrowDown` / `ArrowLeft` / `ArrowRight`），官方 SKILL.md §4.2 明示宿主对方向键的默认行为是**滚动根容器**。因此：①滑动可独立成手势通道（不占单击语义）；②**默认行为仅在 `onKeyUp` 阶段可拦截**，滑动必须在 keyUp 侧 `preventDefault`，否则宿主会把页面滚走；③一次物理滑动连发多个方向键脉冲，需 200ms 消抖窗口只结算一次
6. 标准坐姿下头部无需离开舒适区 ±20°（F-Sys-10）
7. 关键文案在明亮 / 杂乱现实背景下仍须可读（≥ 72% 亮度）

- **游戏画面区取满安全区**：横向 16..464（448 宽）、纵向 44..340（296 高）。无论哪款游戏分册接入，可用画布面积都一致，避免各分册各行其是导致视觉割裂
- HUD 应用名采用 `width = 胶囊宽` + `textAlignHorizontal: CENTER` + `CENTER-aligned TEXT 节点`，**不依赖字宽估算**——文本自动水平居中，y 通过实测偏移公式 `y = 期望墨中心 − size/2 − 1` 精确定位
- B1 是**新分册对接的锚点**：每个游戏分册必须在 B1 框架基础上扩展，HUD 应用名由各分册运行时注入

## 04 · 交互时序与状态机

触控板交互**只依赖单击**（交互 v1.2：双击为宿主保留语义「退出程序」且不可拦截，应用内弃用；v1.1 双击、初版长按均已成历史）。全应用状态机覆盖十屏（A1~A7 主页态 + B1~B4 游戏框架页态，A2 已取消）与全部异常分支：待机单击进入选择态，点亮后单击确认终结本次交互；A4 点亮单击确认 → A6 跳转脉冲（80ms 节拍 + 280ms 待选项渐隐，位置全程锁定）→ A7 loading 等待 → B1 进入游戏；B1 单击唤起 B2 子页面菜单 → 点亮项单击后先走 B3 loading 再切目标态 / **未点亮单击、或挂起 15s 超时 → 先落 B4 继续提示（3s 倒计时；单击或超时再回 B1）**（交互 v1.21：B4 的入边在 v1.2 被删，规格悬挂了三个版本，本版恢复并以 `harness-game.mjs` 的 G1~G4 锁死）；**逃生路径（`onShow` / `onCancel` / MENU 态 IMU 异常 / B3 重试用尽）一律不经 B4、直接回 B1**；切后台 / 摘下眼镜 / 选择（菜单）态 15s 无操作均触发复位分支。

### 触控板单击判定 · 时间线（交互 v1.2）

以 `onKeyDown` 为起点计时；`onKeyUp` 即刻派发单击（**无判定窗口、无延迟**——v1.1 的 300ms 双击窗口随双击语义一并移除，顺带消除了单击固定延迟 300ms 的问题）

| 态 | 判定 | 主页语义 | 二级页语义 |
|---|---|---|---|
| 单击 Tap | 按下后抬起，即刻派发 | 待机进入选择态；点亮态确认选中项；未点亮取消回待机 | 确认当前选中项（战绩页单击返回主页） |

- 拦截规则：仅 `onKeyUp` 中的 `preventDefault()` 生效；`onKeyDown` 阶段不可拦截，系统手势先于应用接收 down 事件。**「双击退出程序」实测无法拦截（v1.2 真机结论）**，`preventDefault` 对单击类默认行为保留为尽力而为，不作为语义前提
- **按压消抖（交互 v1.7，真机取证定案）**：真机取证显示一次物理按压的完整事件形态为 **GlobalHook 对（D/U 间隔 ~6ms）+ 约 483ms 后到达的 Enter 对**——双键码序列，是同一次按压的两个通道。处理规则：①GlobalHook 抬起后 **600ms 内（TOUCH.enterSuppress）的 Enter 对整体吞掉**，不产生第二次单击（否则单击进选择态会被 Enter 对的二次单击打回待机）；纯 Enter 物理键（无近期 GlobalHook）仍按独立单击处理；②**150ms 同键码消抖（TOUCH.tapDebounce）**防长按期间多对 GlobalHook 重复结算。一次物理按压恒等于一次语义；真实连点（间隔 >150ms）逐次生效
- 选择态 / 菜单态 **15s 无确认**视为挂起：自动复位到待机 / 游戏进行态，不触发任何语义。**剩余秒数以 14/500 等宽数字显示在中心圈内（v1.19 新增，见 §14.8）**，与复位共用 `TOUCH.selectSuspend` 计时源
- **待机停采（交互 v1.3）**：主页待机态传感器 `stop()`；单击待机重启传感器并进入选择态，以当前姿态重立会话基准
- **IMU 异常不劫持单击（交互 v1.4）**：待机单击一律进入选择态；IMU 不可用时头控输入恒为 0（`update` 返回 ok:false），选择态提示行切换为「IMU 不可用 · 双击触控板退出」——**宿主双击退出即逃生口，应用内不再依赖退出确认浮层兜底 IMU 失效**；选择态内 15s 无确认仍自动复位待机

### 单击语义矩阵（按页面归属，交互 v1.2）

| 交互场景 | 单击 |
|---|---|
| 主页 / 待机态 | 进入选择态（世界锚定；IMU 不可用也进入，头控恒 0，提示行指引双击退出） |
| 主页 / 选择态 | 确认点亮项并启动；未点亮取消回待机 |
| 游戏进行中 | 唤出暂停选择器；IMU 异常时结束游戏 |
| 游戏内菜单 | 确认点亮项；未点亮继续游戏 |
| 二级页（滚动列表） | 确认当前选中项（战绩页单击返回主页；设置页末行「返回主页」） |
| 退出确认浮层 | 取消退出，回到待机态 |

- **语义唯一原则**：同一时刻同一页面单击只承载一种语义，由当前状态决定，命中即执行
- **双击风险口径**：选择态内快速二次单击（宿主判定为双击）会触发宿主退出程序——属宿主预期行为，应用不补偿；选择态内误双击概率由「未点亮单击=返回待机」的低风险语义自然吸收
- **反馈时序**：单击进入选择态瞬间给触觉 / 听觉短提示（120ms），用户无需看进度即可感知已激活

## 05 · 输入引擎契约（采样 → 解算 → 融合 → 死区 → 滤波 → 映射 → 限速 → 快照）

头控输入在传感器采样与 30fps 渲染之间解耦：传感器持续采样，渲染节拍每帧合并一次「意图快照」。死区、软启动、滤波三级串联，把生理抖动与基线漂移挡在映射之前；直控型与速度型两种映射形态分别服务于「选位置」与「持续移动」。

> **交互 v1.23（v1.54 落地）响应重写**：原流水线的低通与限幅都是**按帧**量（α=0.35/帧、12px/帧），
> 30fps 下等效 τ≈94ms、限速仅 360px/s，且掉帧时延迟还会成倍放大 —— 真机表现为「转头迟钝、跟不上」。
> 现全部改为**按时间**量并接入陀螺快通道，调参集中在 `utils/layout.js` 的 `HEAD`（唯一来源）。
> 回归：转头 20° 阶跃从 **≈400ms 到位**降到 **≈130ms 到位**（`tests/navsim/harness-imu-latency.mjs`）。

### 输入信号链路（八级流水线）

| # | 环节 | 说明 | 备注 |
|---|---|---|---|
| 01 | 采样 | `AbsoluteOrientationSensor` 输出四元数 + **`Gyroscope` 输出角速度**（两者官方 `apis-device.md` 均已确认；`frequency` 只是 best-effort hint） | 双通道 |
| 02 | 解算 | 四元数经**视轴法**（罗德里格斯旋转 VIEW_AXIS）转相对 pitch / yaw，单位度；陀螺按同一套 `SWAP_AXES / SIGN` 约定转视轴角速度（°/s），**无需另行标定轴方向**；**轴通道互换开关 `SWAP_AXES`（交互 v1.5，实机实测开启）**：设备轴系差 90°，交换 yaw/pitch 输出通道使 yaw 恒为水平（左右转头）、pitch 恒为垂直（抬头低头） | 相对基准 |
| 03 | 互补融合 | 陀螺积分出**动态**（零滞后），绝对姿态做**直流与漂移**校正，校正时间常数 τ **自适应**（见下）。陀螺需先经 220ms 同向**准入**才启动积分；轴系判错则永不准入 / 偏离钳制 ±15° / 持续饱和 900ms 自动关闭 —— 三重降级，绝不发散。无陀螺时融合角恒等于绝对姿态（旧口径） | 治本项 |

#### 互补融合的校正时间常数：为什么必须自适应

一阶互补滤波在**恒定角速度偏差**（陀螺零偏）下的稳态解是：

```
稳态偏离(°) = 零偏(°/s) × τ(s)
```

消费级 MEMS 陀螺零偏常在 1~5°/s。τ 固定取 2.5s ⇒ 稳态偏离 2.5~12.5° ⇒ 画面恒漂 20~100px，时间常数 2.5s。真机现象：**进主页选择态后头部完全没动，画面却持续向上/向下飘，只能单击退回待机终止；再次进入有时正常**（"有时正常"＝陀螺尚未准入，或已顶到偏离上限被判不可用）。

故 τ 按**逐轴角速度**插值，取"静止要稳、运动要快"两头：

| 状态 | 判据（该轴角速度 \|ω\|） | τ | 稳态偏离 @3°/s 零偏 |
|---|---|---|---|
| 静止 | ≤ 8°/s | **300ms** | 0.9° ⇒ 落进 1.6° 死区，**肉眼不可见** |
| 中间 | 8 ~ 40°/s | 线性插值 | — |
| 运动 | ≥ 40°/s | **2500ms** | 保住陀螺对融合滞后的相位领先 |

逐轴而非取模：转头时 yaw 在动、pitch 静止 ⇒ pitch 用短 τ 压住零偏，yaw 用长 τ 保住领先，两不相扰。判据取平滑后的角速度估计（τ=90ms）以抗单帧噪声；τ 本身随角速度连续变化，无跳变 ⇒ 画面不抖。

> 回归：`tests/navsim/harness-imu-latency.mjs` J 组（12 项）。零偏 3°/s 静止 8s：位移 **46px → 1.5px**；零偏 8°/s：**→ 3.9px**。

#### 预热期为什么不启用陀螺

上一条治的是**稳态**漂移，但真机还有一条独立路径，且表现更像"一进去就飘"：传感器冷启动时绝对姿态自带收敛误差 `E(t) = E₀·e^(−t/τc)`，而带陀螺的融合角会**滞后于**绝对姿态 —— 一阶滞后对斜坡输入的稳态误差为

```
滞后(°) = τ × 变化率 = 0.3s × 收敛峰值 40°/s ≈ 12°
```

预热窗口一到点，会话基准就冻在这段残差上；之后融合角把残差走完，全部变成可见偏移。实测：收口瞬间 `rel` 只有 −0.13°，2 秒后涨到 −1.49°（**12px**）。

故：**预热期内融合角直接等于绝对姿态**（不积分陀螺、不做互补）。预热期的唯一任务是让基准追上真值，此时陀螺毫无价值（绝对姿态自身都还没收敛）。预热结束再启用陀螺，起点已对齐，静止 τ=300ms 兜住零偏。

| 冷启动条件 | 修复前峰值位移 | 修复后 |
|---|---|---|
| E₀=10° / τc=250ms / 零偏 2°/s | 12px | **< 3px（实测 0.00px）** |
| E₀=20° / τc=300ms / 零偏 4°/s（恶劣） | — | **< 3px** |
| E₀=6° / τc=200ms / 零偏 1°/s | — | **< 3px** |

> **代价**：预热期的跟手性回落到纯绝对姿态口径（= v1.53），仅 900ms；且预热期是限速追赶（30°/s），
> 主动转头超出部分照样立刻进输出。预热期角速度取**绝对姿态差分**而非陀螺（后者含零偏，
> 会让抖动抑制判据误判成"静止"而吞掉真实的慢速转头）。
> 回归：K 组 9 项（三种冷启动参数、预热期不积分、实例重建后基准作废）。
| 04 | 死区 | 偏角 ≤ 1.6° 归零；1.6 ~ 5° 软启动 `f(u)=2u²−u³`（边界**值与斜率双连续**，消除旧版 3° 处 24px 的突跳）；> 5° 线性跟随 | ±1.6 度死区 |
| 05 | 滤波 | 低通**时间常数** τ=45ms（与帧率解耦）；角速度 < 6°/s 且偏角 < 1.8° 判为抖动并抑制；再叠加**角速度前馈**（提前 22ms，上限 2°）抵消低通相位滞后 | 抖动抑制 + 前馈 |
| 06 | 映射 | 直控型 `pos = coef × offset`；速度型 `n = clamp(offset / RANGE, -1, 1)` | 两种形态 |
| 07 | 限速 | 游戏态 ≤ **1200px/s**、选择/菜单态（frozen）≤ **620px/s**，均按 dt 缩放；防瞬移与甩头误选，超出部分顺延到后续帧 | px/**秒** |
| 08 | 意图快照 | 30fps 节拍每帧合并一次，交给渲染层；传感器与渲染完全解耦 | 30fps 输出 |

### 死区与滤波：三级串联的传递函数

| 区间 | 行为 | 说明 |
|---|---|---|
| 死区 0 ~ 1.6 度 | 输出恒为 0 | 吸收呼吸与微颤 |
| 软启动 1.6 ~ 5 度 | `f(u)=2u²−u³` | 边界无突跳，小角度精细可控 |
| 线性区 > 5 度 | 斜率 1 | 1:1 跟随（≥5° 比旧口径更灵敏） |

- **抖动抑制**：|ω| < 6°/s 且偏角 < 1.8°，判为抖动，本帧不产生位移（不累加、不缓存）
- **角速度前馈**：输出 += clamp(0.022 × ω, ±2°)，只在已越过死区时生效（不捅穿死区），且**只作用于像素通道**——增量通道（滚球迷宫 `rel()`）是棘轮式累积，前馈衰减会产生反向位移
- **基线漂移纠正（两档 + 漂移解耦）**：
  - **首选：漂移解耦**（交互 v1.27，陀螺可用且零偏已估准时）。把融合角的变化拆成两笔账：
    `Δfuse = 用户头动（陀螺实测，扣零偏） + 融合漂移`。基准只跟随**后者** —— 用户转头时
    第二项 ≈ 0 ⇒ 幅度完整保留；慢漂时第一项 = 0 ⇒ 全被吸收。两个诉求同时成立，不必在
    回中速率上做取舍。
  - **兜底（无陀螺 / 零偏未估准）**：明显偏离时 ≤ 0.1°/s（保住「保持转头」，旧口径 0.5°/s
    会让画面以 4px/s 慢慢溜回中位）；静止在死区附近时 ≤ **1.5°/s**（v1.58 由 0.35 提高，
    只在死区内生效故不可感知），分界由 1.5×死区 放宽到 **3.5×死区**。选择态/点亮态的
    frozen 仍吸收**死区内**的慢漂（输出本就为 0，不会把选中项拉走）。
  - ⚠ 旧口径的**双稳态陷阱**：分界 1.5×死区 时，慢漂一旦把 rel 顶过分界就切到 0.1°/s，
    净漂移再也收不回来。实测慢漂 0.6°/s 跑 60s 漂 **217px**，且越用越明显 —— 即真机
    「刚开机正常、用一会之后才漂」的由来。

### 两种映射形态

| | 直控型 Direct | 速度型 Velocity |
|---|---|---|
| 用途 | 选位置 | 持续移动 |
| 公式 | `pos = coef × offset`，coef = 8px/°（标准档），限速 1200px/s（菜单态 620px/s） | `n = clamp(offset / RANGE)`，YAW RANGE 30° / PITCH RANGE 20° |
| 适用 | 主页环形入口世界锚定、暂停选择器光标、二级页滚动列表 | 游戏内需持续移动的对象（打飞机左右机动、打砖块挡板） |
| 特征 | 位移与头动角度一一对应；头停即停，头回中则目标回位 | 偏角决定移动速度而非位置；有限视角内可持续移动，无边界回弹 |
| 补充 | 世界锚定公式：`Δpos = −8 × (Δyaw, Δpitch)` | 输出归一化到 −1 ~ 1，由玩法层换算速度 |

> **预热窗口 500 → 900ms（交互 v1.24）**：500ms 是按**旧 3° 死区**定的——残余收敛误差 <3° 时被死区
> 整段吞掉，用户看不到；v1.54 把死区收到 1.6° 后，1.6~3° 这段残余直接显形为「刚进选择态
> 画面就有偏移」。延长**不损跟手性**：预热期是限速追赶（30°/s），主动转头超出部分立刻进输出。
> ⚠ 交互 v1.26 修订：v1.42 这句只保证了**跟手性**（画面在动），不保证**幅度**——追赶会持续把 `rel`
> 拉向 0，选择态 `frozen` 后被吃掉的幅度不会回来。现按头动状态门控（见下节）。
> **读数下限**防的是另一种情况：宿主 `start()` 后若读数迟到（真机 `stop→start` 之间存在不派发
> `reading` 的窗口），纯时间盒会在**一个读数都没到**时就收口，基准直接建在未收敛值上。
> ⚠ 红线（v1.41 事故）：预热只许**追赶**基准，绝不以任何形式清零或削弱输出。
>
> **预热期不积分陀螺（交互 v1.25）**：见上文「预热期为什么不启用陀螺」——带陀螺的融合角在冷启动
> 收敛期会滞后绝对姿态约 12°，基准冻在残差上就是「一进选择态画面就自己飘」。预热期融合角
> 直接等于绝对姿态，预热结束再启用陀螺。另：**传感器实例重建（`_recreate`）时基准一并作废**
> （置 null 交由第 2 个读数重建）——新实例会重新走一遍收敛，与旧基准可能差几十度，而预热
> 追赶只有 30°/s（900ms 最多追 27°），追不完的部分就是一次突然漂移。
>
> **追赶门控（交互 v1.26）**：见下文「预热期追赶为什么必须给转头让路」。

#### 预热期追赶为什么必须给转头让路（交互 v1.26 · 工程 v1.57）

v1.42 的限速追赶是**无差别**的：它把 `rel` 往 0 拉，既吸收融合收敛，也把用户的转头量一并吃掉。
而主页 `_enterSelect()` 每次都 `start()` ⇒ 每次进选择态都重跑 900ms 预热；选择态 `frozen=true`
之后不再纠正 ⇒ **被吃掉的幅度永久丢失**。实测（转头 25°，coef=8px/° ⇒ 期望 200px）：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 静止 2s（预热跑完）再转头 | 188px（94%） | 188px（94%） |
| **一进选择态就转头 25°/s** | **25px（12%）** | **188px（94%）** |
| 慢速大幅 12°/s | 109px（55%） | 188px（94%） |
| 快速 60°/s | **0px（被全部追回）** | 188px（94%） |
| 无陀螺旧设备 25°/s | 25px（12%） | 183px（91%） |

用户观感即「很大幅转头却只有很小移动」，且「有时正常」——取决于有没有撞上那 900ms 窗口。

**为什么必须用陀螺区分**：绝对姿态**无法**区分「读数自己在收敛」与「用户在转头」——冷启动收敛
的变化率可达 80°/s，与主动转头同量级；而任何"是否已收敛"的判据一旦依赖"用户不动"，就与
"用户正在操作"互斥（v1.41 事故的同一条红线）。陀螺测的是**真实头动**，读数自己收敛时它恒为 0，
是唯一干净的区分信号。

门控三档（逐轴独立，参数在 `layout.js` 的 `HEAD`）：

| 状态 | 判据 | 行为 |
|---|---|---|
| 头部静止 | \\|ω\\| ≤ 4°/s | 追赶全速（照旧吸收收敛与漂移） |
| 过渡段 | 4 < \\|ω\\| < 12°/s | 追赶按线性衰减，预热窗口同步减速推进 |
| 持续头动 | \\|ω\\| ≥ 12°/s 满 100ms | **锁定该轴基准**，本会话不再追赶，并结束预热让陀螺接管 |

> 锁定必须是**终止**而非暂停：转头结束后追赶若恢复，会把转头量慢慢拉回 0（实测 60°/s 快转稳态
> 回到 0px）。锁定即 `warming=false` —— 否则陀螺一直被"预热期不积分"挡在门外，跟手性退回 v1.53。
> 陀螺不可用时退化为绝对姿态差分速率；此时**不冻结预热窗口**（收敛期速率同样很高，冻结会让
> 预热永不结束，破坏 v1.42 的纯时间盒语义），只让门控负责"不吃幅度"，残余 ~1.3° 仍落进死区。

## 06 · 校准与基准姿态管理

基准姿态分两级：会话基准服务于导航，游戏基准服务于玩法。主页刻意**不预置姿态基准**，进入游戏前才走正式校准，以避免主页长时间静止造成的缓慢漂移污染游戏基准。漂移纠正优先走**漂移解耦**（用陀螺把 Δfuse 拆成用户头动与融合漂移，基准只跟随后者，故不受冻结影响）；陀螺不可用时回落到两档（明显偏离 ≤ 0.1°/s、死区附近 ≤ 1.5°/s），且选择态 / 点亮态 / 暂停期间只吸收死区内的慢漂。

### 正式校准流程（2 秒静息 + 方差校验）

触发时机：

| 场景 | 说明 |
|---|---|
| 首次进入游戏 | 强制，不可跳过 |
| 累计偏航超 ±45° | 游戏内保护触发 |
| 手动触发 | 教学 / 校准 / 设置页，或暂停中 |

流程：

1. **提示**：屏幕中央显示「请保持自然平视，注视中央 2 秒」（72% 主文本）
2. **静息采样**：连续 2s 采集姿态序列（约 120 帧），采样期间不消费任何头动输入
3. **方差校验**：计算 pitch / yaw 序列方差，低于阈值判为稳定，超阈值判为不稳定
4. **写入基准**：写入 pitch0 / yaw0，给 120ms 短提示后进入游戏（游戏基准）
5. **失败分支**：提示「未能获取稳定姿态」并重试，最多 3 次；第 3 次仍失败则用默认基准并标记未校准

口径：校准全程为模态界面，仅单击可用（v1.2：应用内已无双击手势）；校准期间暂停漂移纠正。

### 两级基准与漂移纠正生效矩阵

| 基准层级 | 建立时机 | 精度要求 | 生效范围 |
|---|---|---|---|
| 会话基准 | 应用启动 / 从后台恢复 | 低（无需静息） | 主页、二级页、暂停选择器 |
| 游戏基准 | 进入游戏前正式校准 | 高（2s 静息 + 方差校验） | 玩法层、体感摘要统计 |

漂移纠正生效矩阵（陀螺可用时走**漂移解耦**，下表是**无陀螺兜底**路径；速率 ≤ 1.5°/s）：

| 界面状态 | 漂移纠正 | 说明 |
|---|---|---|
| 主页 / 待机态 | 生效 | 缓慢回填会话基准，抵消长时间佩戴的基线漂移 |
| 主页 / 选择态 | 冻结 | 避免已锚定的入口阵列被缓慢拉走，导致选择漂移 |
| 主页 / 点亮态 | 冻结 | 保持已点亮目标稳定，避免松手瞬间判定跳变 |
| 暂停选择器展开 | 冻结 | 保证左右位判定稳定，暂停状态下不消耗头动 |
| 游戏进行中 | 生效 | 与会话基准同源；玩法层独立维护自己的相对坐标系 |

- **无效数据处理**：传感器返回 null 或连续多帧无变化时暂停纠正，且不写入基准，恢复后提示重校准
- **强制重校准**：游戏内累计偏航 |Δyaw| > 45° 触发，中断当前局并回到正式校准流程
- **暂停中快速重校准**：复用 2s 静息流程，完成后直接回到暂停界面，不重开当前局

### 校准三屏规格（E1 / E2 / E3）

| 屏 | 名称 | 规格 |
|---|---|---|
| E1 | 校准引导 | HUD 条 24px：左「校准」右「1 / 3」计数；中央 Ø120 导向圆（24%）+ Ø36 原点（48% 底 + 72% 芯）；主文案 16/500 与 14 均取 72%，底部注释 11 取 48% |

## 08 · 二级页滚动列表范式（单轴 pitch 直控）

二级页不使用世界锚定，而是「视窗固定、内容滚动」的直控滚动：抬头即上滚、低头即下滚，头停即停。选中项与滚动位置强绑定，确认必须由单击显式触发，滚动本身不产生任何状态跳转。

### 滚动参数（裁决 D-02 统一口径）

| 参数 | 取值 | 说明 |
|---|---|---|
| 参与轴 | 单轴 pitch | yaw 不参与，避免左右误触造成列表横向抖动 |
| 全程覆盖 | ± 18° | 抬头到底对应首项，低头到底对应末项 |
| 单帧限幅 | ≤ 12px | 30fps 下最快约 360px/s，防止甩头瞬移 |
| 滚动方向 | 抬头 = 上滚 | 内容下移、视窗相对上移，符合抬头看更上面的直觉 |
| 进入方式 | 当前 pitch 为起点 | 不做回中，避免进入瞬间列表跳动一下 |
| 边界处理 | 24% 边界标记 | 到达首尾后停止滚动，显示边界标记但不回弹 |
| 惯性与阻尼 | 无惯性 | 头停即停，与直控型零迟滞的体感保持一致 |

- **裁决 D-02**：滚动参数统一为 ±18° / 每帧 ≤ 12px，三个二级页不各自定义，避免同一动作在不同页面手感不同
- **滚动与确认解耦**：滚动只改变选中项，不改变页面状态；任何跳转都必须由单击显式触发

### 操作映射与列表项视觉三态

| 操作 | 语义 |
|---|---|
| 抬头 | 列表向上滚动，选中项上移 |
| 低头 | 列表向下滚动，选中项下移 |
| 单击 | 确认当前选中项（战绩页 = 返回主页；设置页末行 = 返回主页） |

> 交互 v1.2：原「双击返回主页」行随双击语义弃用而移除，返回主页改为单击承载（见 §07 返回语义）。

| 列表项状态 | 编码 |
|---|---|
| 未选中项 | 仅 1px / 48% 描边，无底纹 |
| 选中项 | 12% 底纹 + 100% 描边 + 2px 焦点竖条 |
| 确认中 | 外加 72% 强调环，200ms 后触发 |

### 三种头控模式对比（世界锚定 / 滚动列表 / 游戏内）

| 维度 | 主页选择态（世界锚定） | 二级页滚动列表 | 游戏内 |
|---|---|---|---|
| 参与轴 | 双轴 yaw + pitch | 单轴 pitch | 按玩法，单轴或双轴 |
| 映射形态 | 直控型，8px/° | 单轴滚动，±18° 覆盖全程 | 直控型或速度型，由分册定义 |
| 什么在动 | 入口阵列随头动反向位移 | 列表内容滚动，视窗固定 | 光标或游戏对象跟随头动 |
| 光标本体 | 屏心原点固定不动，升级为光晕 | 无独立光标，选中项即焦点 | 按玩法，可为光标或实体 |
| 激活条件 | 单击触控板激活（v1.2） | 进入页面即生效 | 进入游戏即生效 |
| 确认方式 | 点亮后单击确认，未点亮单击取消 | 单击确认 | 单击唤出暂停选择器 |
| 漂移纠正 | 冻结 | 生效 | 生效 |
| 传感器订阅 | 待机停采；单击进入选择态时 `start()` + 以当前姿态重新锚定，60Hz（交互 v1.3/1.4） | 常驻 60Hz | 常驻 60Hz |

**口径**：三种模式互斥，任一时刻只可能处于其中一种；跨模式切换时必须重置基准与选中态，避免上一模式的残余位移被带入新模式。

## 09 · 游戏内暂停选择器（屏内直控光标）

游戏内退出与暂停统一收敛到单击手势（交互 v1.2，v1.1 为双击，初版为长按）：游戏中单击唤出暂停选择器，菜单内点亮单击确认、未点亮单击直接继续游戏。暂停选择器与主页的关键差异在于：主页是世界锚定（原点不动、入口阵列动），选择器是屏内直控光标（原点在屏内真实移动）。画面变暗一律靠降低元素自身 alpha，禁止黑色遮罩。

### 三屏规格（D1 / D2 / D3）

| 屏 | 名称 | 规格 |
|---|---|---|
| D1 | 选择器展开（原点吸附右位） | 画面冻结后全部元素 `globalAlpha` 渐隐至 0.15（≥200ms），仅选择器与原点维持高亮。左位为暂停（双竖线 + 文字），右位为主页（回折箭头 + 文字），双通道冗余。原点在屏内真实移动到右位并吸附，右位呈三通道编码。底部文案「转头移动原点 · 单击确认 · 未点亮单击则继续」 |
| D2 | 已暂停界面（画面恢复 40%） | 吸附左位松手后进入持久暂停：静止画面亮度从 0.15 恢复到 40%，文案区仅用 6% 极弱底纹抬底，不叠加黑色遮罩。单击恢复游戏，恢复后给 1 秒倒计时保护，防止刚恢复就被判定受伤 |
| D3 | 右位退出确认浮层（3s） | 吸附右位松手后弹出确认浮层：288×140 面板用 6% 底纹 + 72% 边框，文案两级（16/72% 主问句「确定退回主页？」+ 12/48% 后果说明「当前进度将丢失」）。Ø44 环形倒计时 + 13px 数字为唯一 100% 元素；单击取消，超时记录本局成绩后返回主页 |

### 暂停选择器状态转移与关键参数

| 阶段 | 触发条件 | 画面处理 | 结果 |
|---|---|---|---|
| 唤出 | 游戏内单击触控板（v1.2） | 冻结，全部元素 `globalAlpha` 渐隐至 0.15（≥200ms） | 浮现两向选择器与中央原点，原点为屏内直控光标 |
| 无缝继续 | 未点亮直接单击 | 选择器淡出，画面亮度恢复 | 从冻结帧无缝继续（最高频路径，必须零负担） |
| 已暂停 | 吸附左位后单击 | 画面静止，亮度从 0.15 恢复到 40% | 显示「已暂停 · 单击继续」；单击恢复，1s 倒计时保护 |
| 退出确认 | 吸附右位后单击 | 维持 0.15，浮层用 6% 底纹 + 72% 边框 | 3s 确认浮层；单击取消，超时记录成绩后返回主页 |
| 挂起 | 选择器 > 15s 无任何操作 | 同左位处理，画面恢复到 40% | 直接转入已暂停界面，视为放弃本次操作 |
| 挂机释放 | 已暂停状态无输入 ≥ 3 分钟 | 释放传感器订阅，停止渲染 | 自动挂起；单击唤醒后走快速重校准再恢复 |

- **禁止黑色遮罩**：透明屏上纯黑即现实背景，遮罩无效；一切「变暗」只能通过降低元素自身 alpha 实现，过渡 ≥ 200ms
- **与主页的分工**：主页是环境级锚定（原点不动、入口阵列随头动反向位移）；选择器是页面级屏内直控光标（原点在屏内真实移动并吸附）
- **双通道冗余**：每个功能位同时提供图形图标与文字标签，避免小视场下纯图标的识别歧义；标签文字与图标水平居中对齐

| F-Sys-09 | 休息关怀 | 单局累计大幅摆头超过 300 个有效指令周期时弹出提示「晃得有点久了，休息一下眼睛和脖子～」（可跳过） | 本册 | 不落盘 |
| F-Sys-10 | 舒适区约束 | 所有界面中立位即布局重心附近，标准坐姿下头部无需离开舒适区超过 ±20° | 本册 | 不落盘 |

- **存储口径**：全部使用同步写入 `setStorageSync`，避免异步竞态；写入失败仅 Toast 提示一次，不阻塞当前局游戏
- **读档容错**：JSON 解析失败静默重置为空档案，绝不崩溃（NFR-06）；空档案在战绩页显示「暂无记录」，不显示占位数字

### F-Sys-09 休息关怀触发机制

| 项目 | 取值 | 说明 |
|---|---|---|
| 触发条件 | 有效指令周期 > 300 | 单帧位移超出死区阈值即计一个周期；30fps 下约等于持续摆头 10 秒 |
| 提示形式 | 非模态浮层 | 12% 底纹 + 72% 边框，不冻结游戏、不停传感器 |
| 交互 | 单击即关闭，可跳过 | 不强制中断；同局只提示一次，关闭后本局不再打扰 |
| 计数重置 | 切游戏 / 回主页清零 | 不跨局累计，避免正常游玩被反复打扰 |
| 文案 | 「晃得有点久了，休息一下眼睛和脖子～」 | 语气轻松，不制造焦虑；浮层出现在屏幕下方 1/3，不遮挡核心玩法区域 |

- **设计意图**：头控是体力活，关怀提示是本产品唯一主动打断用户的场景，因此必须可跳过、非模态、同局仅一次
- **计数口径**：只统计「有效指令周期」，即真正产生位移的帧；静止、抖动被抑制的帧不计入，避免误判

### F-Sys-10 舒适区与角度阈值谱

| 区间 | 范围 | 系统行为 |
|---|---|---|
| 死区 | 0 ~ 3° | 输出恒为 0，吸收呼吸与微颤 |
| 舒适区 | ≤ 20° | 全部界面中立位，长时间停留无颈部负担 |
| 常用区 | 20 ~ 30° | 速度型满速角（偏航 30° / 俯仰 20°）；计入关怀计数 |
| 极限区 | 30 ~ 45° | 仅快速甩头可达 |
| 保护 | ≥ 45° | 强制重校准（累计偏航保护线） |

其它阈值：抖动抑制 |ω| < 10°/s 且 < 4°；滚动列表覆盖 ±18°；单帧限幅 ≤ 12px；关怀阈值 300 有效指令周期；选择（菜单）态无操作超时 15s；挂机释放 ≥ 3 分钟。

- **设计约束**：任何界面的常用操作区间都应落在舒适区（≤ 20°）内；需要超出舒适区才能完成的操作，必须重新设计交互或调整布局
- 退出应用置于正下方环位，正是利用「需刻意低头」这一超出舒适区的动作作为天然防误触屏障

## 11 · 数据结构与接口契约

主页与游戏分册之间只通过两份契约通信：`GameManifest` 描述「这是什么游戏、放在环上哪一位」，`GameResult` 描述「这一局打成了什么样」。结算页只消费 `GameResult`，不反向依赖任何游戏内部状态。

### GameManifest（游戏清单）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | String | 游戏唯一标识 |
| `name` | String | 展示名，≤ 4 字 |
| `page` | String | 页面路由路径（**无前导斜杠，与 app.json `pages` 注册格式一致**，交互 v1.10——真机实测带 `/` 前缀的路由跳转不生效） |
| `ringPos` | 枚举 8 值 | T / RT / R / RB / B / LB / L / LT |
| `difficultyRank` | 1 .. 5 | 难度阶梯，左上 1 到 右 5 |
| `axisLabel` | String | 轴标签，如「单轴 左右」 |
| `tutorialLine` | String | 一句话教学文案 |
| `iconId` | String | 圆环描边图标资源标识 |

- **F-HOME-01**：五款游戏的 `ringPos` 与 `difficultyRank` 必须与需求表逐项一致，主页不做容错映射
- 产出方：各游戏分册；消费方：主页环形入口、教学页、战绩页
- 上半环五位为游戏位，RB / B / LB 为系统位与销毁位，不参与 `difficultyRank` 排序

### GameResult（本局结果）

| 字段 | 类型 | 说明 |
|---|---|---|
| `score` | Number | 本局得分 |
| `cleared` | Boolean | 是否通关 |
| `reachedLevel` | Number | 到达关卡 / 波次 |
| `durationSec` | Number | 本局时长（秒） |
| `motion.yawUtil` | 0 .. 1 | 偏航映射平均利用率 |
| `motion.pitchUtil` | 0 .. 1 | 俯仰映射平均利用率 |
| `motion.yawAmpDeg` | Number | 偏航幅度（度） |
| `motion.pitchAmpDeg` | Number | 俯仰幅度（度） |
| `motion.tapCount` | Number | 单击次数 |
| `motion.tapLatencyMs` | Number | 平均响应时延（毫秒） |
| `extra` | Array ≤ 2 | 专有指标，label ≤ 6 字 |

- **F-HOME-05**：GameOver / 通关 / 暂停选择器右位超时三条路径都必须产出 `GameResult`，否则按 `score=0`、`cleared=false` 兜底

### 存储键与读写时机

| 存储键 | 结构 | 时机 |
|---|---|---|
| `hi_{gameId}` | Top3 数组 | 成绩进入即落盘 |
| `settings` | 灵敏度 / 音效 | 变更即刻落盘 |
| `tutorial_seen` | 游戏 id 布尔表 | 教学关闭时写入 |

| 读写与容错 | 行为 |
|---|---|
| 写入方式 | `setStorageSync` 同步写 |
| 写入失败 | 仅 Toast 一次，不阻塞 |
| 读取失败 | 静默重置为空档案 |
| 空档案表现 | 「暂无记录」，无占位数字 |

结算页只消费 `GameResult`，战绩页只读 `last_{gameId}`（老存档回退 `hi_*`），两者互不反向依赖。

## 12 · 异常与边界场景处理

透明眼镜的使用环境远比手机恶劣：戴歪、行走颠簸、突然摘下、甩头、连点都会发生。所有异常的处理遵循同一条原则——**退出通路必须永远可达**，任何情况下都必须保留退出能力，且绝不出现「卡在选择态却既无法确认也无法取消」的中间态。**宿主「双击触控板 = 退出程序」不可拦截（v1.2 真机结论），作为宿主级兜底退出通路；交互 v1.4 起 IMU 失效不再劫持主页交互（照常进选择态、头控恒 0），逃生口 = 宿主双击退出 + 选择态提示行指引。**退出确认浮层（A5）仍作为点亮「退出应用」入口后的常规确认通路，不依赖头动数据（单击取消 / 3s 超时）。

| 场景 | 处理策略 | 涉及模块 |
|---|---|---|
| 戴歪了 / 基准失真 | 支持在教学页与暂停选择器重校准；自动漂移纠错兜底缓慢跟随 | 校准流程、漂移纠正 |
| 行走颠簸途中操作主页 | 低通滤波 + 死区屏蔽小幅噪声；角速度长期超限时提示「当前环境不适合游玩」并暂停选择态 | 输入引擎、主页状态机 |
| 玩家突然摘下眼镜 | 依宿主行为切后台，主页自动取消选择态并复位原点与入口位置；二级页保持当前滚动位置 | 生命周期、主页、二级页 |
| 快速连环甩头 | 速度型因限幅不会瞬移；主页选择态入口反向补偿连续随动（入口暂出视野属正常，转回即可） | 单帧限幅、世界锚定 |
| 高频连点触控板（主页） | **双键码合并 + 同键码消抖（v1.7）**：一次物理按压的 GlobalHook 对与 483ms 后的 Enter 对合并为一次语义（Enter 抑制 600ms）；同键码消抖 150ms；真实连点（间隔 >150ms）逐次生效：待机单击进选择态、选择态内未点亮单击回待机，无中间卡死；快速二次按压若被宿主判为双击则退出程序，属宿主预期行为 | 单击判定 |
| 选择态挂起 | 选择态 15s 无确认自动取消回待机，原点与入口位置一并复位 | 主页状态机 |
| 传感器权限失败 / error | **主页不受影响**（交互 v1.4）：待机单击仍进入选择态，头控输入恒为 0；选择态提示行显示「IMU 不可用 · 双击触控板退出」；**宿主双击退出即逃生口**，应用内不再单设 IMU 失效专用通路。游戏页右上 HUD 显示 `IMU状态异常`（空心圆点），游戏内单击唤菜单时 IMU 异常直接结束游戏进结算 | HUD、状态机、游戏页 |
| 存储写满 / 异常 | 写入最高分失败仅 Toast 一次提示，不影响当局游戏进行 | F-Sys-01 存储层 |
| 读档 JSON 解析失败 | 静默重置为空档案，绝不崩溃（NFR-06） | 存储层 |
| 应用切后台 | 立即 `stop()` 传感器；回前台后主页回待机态；选择态下次单击进入时重新锚定（无需预置基准） | 生命周期、输入引擎 |

- **统一原则**：任何异常都不允许出现「卡在选择态却既无法确认也无法取消」的中间态；超时、切后台、IMU 失效三条路径都必须能自动复位到明确的已知状态
- **退出通路唯一保留**：IMU 失效时禁用头动相关语义（点亮 / 选择），但退出确认浮层（A5）作为通用退出通路不依赖头动数据，必须保持可用（单击直达；单击触控板取消 / 3s 超时退出）

**为什么 v1.20 要把 `GLOW` 拆成三套**：v1.19 里点亮项与中心共用 `GLOW.core`。真机取证反馈"中心光晕偏亮、压过入口"，直接降 `GLOW.core` 会**连带削弱点亮态**——而点亮强度是"我选中了它"的唯一语义反馈，弱化后用户分不清"选中了"还是"只是靠近"。拆出 `GLOW.lit` 后中心可独立降亮，**选中语义不受影响**。

- 三态的中心**只有一个圆环**——不再是「68×68 底纹 + 52×52 强调环 + 36×36 本体」的三层同心结构。"光晕"由光晕面本身承担，环只负责画出明确的边界。
- **v1.19 删除**：待机准星的四正向刻度 r26~30、激活中心的四斜向 45° 刻度 r34~40。理由：屏心区域要让位给**倒计时数字**与 loading 图标，任何刻度都会在中心切出碎线；且"中心是否活跃"改由倒计时数字直接表达，比刻度更能说明"还有多久超时"。
- 三屏的 loading 核心**共用一个实现** `drawLoadingCore()`（`utils/ring.js`），几何常量集中在 `utils/layout.js` 的 `LOADING_CORE`、`PULSE`、`GLOW`；改一处即三屏同步。

#### 点亮标签 · 近端对齐（v1.20 · 修「紧贴图标被遮挡」）

**真机现象**：转头靠近某入口时功能名浮出，但名称**紧贴功能图标**、被 48×48 圆环与图标压住看不清。

**根因不是偏移量不够，而是锚点语义错配**：`utils/draw.js` 的 `text()` 默认 `textAlign='center'` / `textBaseline='middle'`，即**锚点是墨盒中心**。旧实现 `drawEntryLabel` 把文字**居中**于「入口中心 + `LABEL_OFFSET`(36)」，于是

```
近端 = 36 − 字宽 / 2
```

| 名称 | 字数 | 字宽（11 × 0.99 × n） | 旧近端（36 − w/2） | 实际位置 |
|---|---|---|---|---|
| 打飞机 | 3 | 32.7 | **19.7px** | 已落在 r24 圆环**内部**，压住圆环描边 |
| 重新游戏 | 4 | 43.6 | **14.2px** | 压到 24px 图标上 |
| 导弹指挥部 | 5 | 54.5 | **8.7px** | 几乎盖住整个 24px 图标 |

**字数越多，近端越往里缩、越被遮挡** —— 这解释了为什么"把偏移调大一点"治标不治本：3 字刚好、5 字就一定糊。

**规格（v1.20）**：文字的**近端边缘**恒落在「圆环外缘 + `LABEL_GAP`」处，再背向入口向外生长，与字数彻底解耦。

```js
ENTRY_R    = 24   // 入口圆环半径（48×48 · cornerRadius 24）
LABEL_GAP  = 8    // 标签近端与圆环外缘的净空
// 近端 = ENTRY_R + LABEL_GAP = 32（自入口中心量起）
// 墨中心 = 入口中心 + u × 32 + s × (字宽 / 2)   ← u 为背向屏心单位向量，s 为其符号
```

| 项 | 取值 |
|---|---|
| 字号 / 字重 | 11 / 500（同 §01 标签级） |
| 单行墨高 `LABEL_H` | 13 |
| 越界处理 | 水平越出安全区时**整体镜像到入口另一侧**；垂直方向 `clamp` 进安全区 |
| 测宽 `textWidth()` | `measureText` 不在 AIUI 确认 API 范围内，真机可能返回 0 / undefined → **与字宽估算取大值**（CJK ≈ 0.99 × size、拉丁 ≈ 0.52 × size）。取大非取小，保证底框永不裁切 |

### 14.7 确认 → loading 的淡出节拍（v1.18 · 消除「跳跃感」）

**用户反馈**：「选中功能点击确认后转到 loading 的效果不是很流畅，有点跳跃」。

#### 根因：三处瞬变发生在同一帧

| # | 瞬变 | 用户看到的现象 |
|---|---|---|
| ① | 确认瞬间 `engine.recenter()` 把头控偏移清零 | 八个入口**当帧**从当前锚定位弹回中心对称位 —— 最大的单一跳跃源 |
| ② | A6 → A7 的切换帧把所有入口（含选中项）从分档亮度一帧打到 6% | 亮度断崖：选中项 100% → 6% 只用了 1 帧 |
| ③ | 中心从「激活中心」硬切到「loading 核心」，波纹道数 2→3、上限 r50→r62 | 中心换脸 + 波纹道数/半径同时跳变 |

三者叠加，主观感受就是"啪的一下跳过去了"。

#### 规格：三条曲线共用同一条 fade

`LAUNCH_FADE`（`utils/layout.js`，A6/A7 与 B3 共用，两处节奏严格一致）：

| 参数 | 值 | 含义 |
|---|---|---|
| `delayMs` | 80 | 确认后先留一个「已确认」可见节拍，再起淡出（按下即糊反而看不清） |
| `durMs` | 280 | 淡出时长：分档亮度 / 点亮三通道 → 6% 隐藏档 |
| `coreXMs` | 160 | 中心「激活中心 → loading 核心」的交叉淡入时长（两态同时在场） |
| `labelFrom` / `labelTo` | 0.25 / 0.8 | 功能名标签的渐入区间（按淡出进度计） |

- `A6_MIN_MS = delayMs + durMs = 360`：**淡出结束的同一帧才切 A7**，故 A6 最后一帧与 A7 第一帧逐像素相同，切换点上没有任何亮度 / 半径 / **道数**跳变（v1.19 起为光晕波纹）。
- `LOADING_MIN_MS = A6_MIN_MS`：B3 同样等淡出走完再发 `navigateBack`（原 200ms 会让"还没看清就跳走了"）。

#### 收束规则

| 规则 | 说明 |
|---|---|
| `fadeTo(a, f) = a + (P06 − a) × f` | 所有通道（框 / 图标 / 点亮三件套）统一沿 fade 收束；**f=1 直接返回常量 P06**（浮点插值会得 0.06000000000000005，破坏"逐像素相同"契约）。v1.19 删除装饰层后，通道由 4 个降为 3 个 |
| `lit`（视觉）与 `sel`（语义）分离 | `lit` 不受 fade 影响 → 点亮项也是**渐隐**而非"消失"；`sel = lit && f < 0.5` → 淡出过半后 `pickLit()` 恒 null，状态语义不受影响 |
| 标签提前隐去 | 标签 alpha 另乘 `labK(f)`，在 fade 0.25~0.8 区间渐隐 —— 避免 A7 中心已有功能名时外圈再挂一个 6% 的重复名字 |
| 位置锁定（关键） | **A6/A7 全程持续消费 IMU**，入口相对头部坐标系一动不动，只做亮度渐隐。确认路径**禁止 `recenter()`**；`recenter()` 全项目只剩 A5 退出确认分支与 `resetToIdle()` 两处 |
| 中心交叉淡入 | A6 头 `coreXMs` 内：激活中心以 `(1−k)` 淡出、loading 核心以 `k` 淡入，两者同场；不再是硬切 |
| 波纹连续 | 道数 `2 + fade`（**支持小数**：固定 3 个相位槽位 + 末道按小数渐入）、上限 `r1 + (r2 − r1) × fade`，峰值 α 沿 `PULSE.ripple` 插值。旧实现用 `i/n` 分配相位，n 从 2 变 3 时全环相位集体重排 —— 这是跳跃感的第三个来源 |
| A5 / B4 例外 | 浮层态仍为**瞬时收束 + 下层固定居中**（浮层自身的出现就是瞬时的，且下层需回到对称位） |

#### 时序

```
A4 选择态（入口分档可见、选中项点亮）
  └─ 单击确认 ─► A6（t=0…80ms）入口保持原样、中心激活态淡出 / loading 核心淡入
                  └─（80…360ms）入口沿 fade 收束至 6%，位置全程锚定头部
                                 波纹 2 道 r50 → 3 道 r62，功能名渐入
                                 └─ t=360ms 切 A7：与上一帧逐像素相同
                                                 └─ 3 道光晕波纹循环不息，直到 B1 打开
B2 → B3 同构（**R = 114** 二向菜单 + 画面区同步渐隐）
```

### 14.8 中心选择态倒计时（v1.19 新增）

选择态是有超时（15s）的临时态，但此前**画面上没有任何元素表达"还剩多久"**——用户只能感到"突然就退回待机了"。v1.19 在中心圈内补上倒计时数字。

| 项 | 规格 |
|---|---|
| 内容 | 剩余秒数，**`ceil(剩余ms / 1000)`**，最小值 1（不显示 0） |
| 字体 | **14 / 500 等宽**（`CORE_COUNT = { size: 14, weight: 500, mono: true }`），等宽避免逐秒跳宽 |
| 位置 | 中心圈几何中心 (240,176)，水平垂直均居中 |
| 亮度 | fill 100%（与激活中心环同档，是屏心最高亮元素） |
| 计时源 | `TOUCH.selectSuspend`（15s），与 §04「选择态 / 菜单态 15s 无确认视为挂起」**同一计时源**，数字归零与状态复位发生在同一帧 |
| 实现 | `drawCoreCountdown(ctx, cx, cy, sec, alpha)`（`utils/ring.js`） |

**显示 / 不显示矩阵**：

| 屏 / 态 | 是否显示 | 说明 |
|---|---|---|
| A1 待机 | 否 | 待机无超时语义，且中心准星已有 r2.5 实心点占位 |
| **A3 选择中** | **是** | 未点亮时也倒计时——超时后回待机 |
| **A4 已选中（点亮）** | **是** | 点亮不暂停计时，仍需提示"不选就退回" |
| **B2 菜单态** | **是** | 与 A3 同构，超时回 B1 继续游戏 |
| A5 / B4 浮层 | 否 | 浮层自带 3s 环形倒计时，中心圈不显示（A5 中心原点本就不画） |
| A6 / A7 / B3 loading | 否 | 中心被 loading 核心（图标 + 标签）占据，且淡出期不再有"取消"语义 |

**为什么不做成环形进度**：中心圈 r18 直径仅 36px，画环形进度会与圈的描边重叠成一团；而数字在等宽字体下宽度恒定，r18 圈内放得下 1~2 位数字（14px 等宽数字宽约 8.4px/位）。同时数字比弧长**更易读**——用户余光扫一眼就能读出"还剩 7 秒"。

**与浮层倒计时的分工**：中心倒计时管「选择态超时」（15s，细粒度数字），浮层倒计时管「销毁性操作确认」（3s，环形进度 + 大号数字）。两者不同屏、不并存，无需统一形态。

### 14.6 实现约束（画布沉淀）

1. **整圆表达**：Ardot 对 `<circle>` 解析不可靠且单 frame 图形元素 >3 即失败；统一用双半圆弧 path `M(cx-r),cy a r,r 0 1,0 2r,0 a r,r 0 1,0 -2r,0` 表达整圆，多圆靠 M 子路径合并进单个 path（每层 ≤3 个 path）。
2. **刻度/放射线一律用填充四边形**（4 顶点闭合），纯线段 path 会被判退化几何；禁 `<line>`。（v1.19：刻度与放射线已全部删除，本条仅在回补旧装饰或新增同类元素时适用）
3. 属性直写到每个 path（fill/stroke 不继承）；坐标全部预计算为绝对值（transform 不可靠）。
4. 几何生成脚本：`.cache/gen_polish.py`（输出即 batch_edit 可粘贴操作行）；像素探针 `.cache/pngprobe.py`。

## 附 · 变更记录 v1.13（导航「落地握手」——nav:ok 但页面未跳转）

**现象**：选中功能后单击，底部取证行显示 `nav:ok pages/game?gameid=missile`，但屏幕仍停在主界面，没有跳转。

### 根因：Router API 的 success 不是成功证据

官方 `apis-wx.md` Router methods 原文：

```
- navigateTo(options) requests page navigation.
- redirectTo(options) requests page redirection.
- navigateBack(options?) requests backward navigation.
- These methods call success() and complete() when present.
```

**没有 fail 路径**（System methods 中对 `setBackgroundColor` 更是明写 "does not expose a fail() path"）。因此 `success` 是**无条件回调**，语义是"请求已发出"，而非"页面已切换"。真机返回的 `nav:ok` 只证明了请求被接收，与是否跳转无关——两者完全吻合。

### 放大器：v1.12 把 `_pause()` 挂在了 success 上

v1.12 的实现在 `success` 回调里调用 `_pause()`（停渲染循环 + 停 IMU）。回调一到，主页渲染循环立即停止，**画面当场定格在主界面**，后续所有重试、兜底与取证都失去执行机会。这才是"用户看到的永远是主界面"的直接成因。

### 变更

| # | 变更 | 说明 |
|---|---|---|
| 1 | **落地握手**判定 | `utils/storage.js` 新增 `armNavProbe()` / `markNavLanded()` / `navLanded()`：跳转前置 `__navProbe='req'` → 目标页 `onLoad` 置 `'landed'` → 主页 tick 轮询，命中才算真跳转 |
| 2 | `_pause()` 只在落地后调用 | 从 `success` 回调中移除；`onKeyUp` 补发也加 `!navLanded()` 守卫，避免打断已跳转的页面 |
| 3 | gameId 改走 storage | `setEntryGameId()` / `takeEntryGameId()`；url 保持裸路径 `pages/game/game`，排除宿主路由对带 `?query` 路径精确匹配失败 |
| 4 | 多方式重试 | 未落地则每 `NAV_PROBE_MS`(700ms) 换一档：`navigateTo → redirectTo → navigateTo`，共 `NAV_MAX_STEP`(3) 档，约 2.1s |
| 5 | 失败可感知 | 配额用尽显示 `nav:dead <url>` 并复位待机，用户可重试而非卡死 |
| 6 | 诊断文案对齐语义 | `nav:req<n> <how>`（请求已发）/ `nav:landed s<n>`（已落地，n=命中档位）/ `nav:dead <url>`（宿主不受理） |

### 验证

- `node --check` 三个改动文件通过；`check-multifile` 8 项全过（21 个 JS 文件）
- `tests/navsim/` 本地实证 **14/14 PASS**，含真机复现场景「success 回调但页面从不落地」：

| 退出分支回归 | 只发 1 次；静默 2s 判定失败并给出双击退出指引 |

### 两个关键发现

**① storage 不可用会造成「静默假阴性」**

```
- Sync storage methods throw when storage support is unavailable
```

### 一、半径 130 → 114

**收益**：

| 项 | R = 130 | R = 114 |
|---|---|---|
| 点亮所需转头量 | (130−48) / 8 = 10.25° | **(114−48) / 8 = 8.25°** |

降幅约 **−20%**。依据：画布底色 `#080A09` 近全黑，同样的 α 比参考图（暗灰室内背景）冲击更强；AR 透明屏"越亮越可见"，中心光晕是**环境氛围**而非信息载体，压过 24% 档的环形入口就本末倒置了。

#### 关键决策：把 `GLOW` 拆成三套，点亮光晕不跟着降

v1.19 里点亮项与中心**共用 `GLOW.core`**。若直接降它，会连带削弱点亮态——而点亮强度是「我选中了它」的**唯一语义反馈**，真机并未反馈它偏亮。弱化之后用户就分不清"选中了"还是"只是靠近"。

```js
export const GLOW = {
  core:  [[0, 0.24], [0.55, 0.08], [1, 0]],  // v1.20 真机下调（原 0.30 / 0.10）
  lit:   [[0, 0.30], [0.55, 0.10], [1, 0]],  // v1.20 新增独立常量，保持 30%
  panel: [[0, 0.20], [0.55, 0.08], [1, 0]],  // 不变
};
```

三者层级关系反而更清楚了：**点亮 0.30 > 中心 0.24 > 面板 0.20**。

### 二、点亮标签：居中锚定 → 近端对齐

**根因是锚点语义错配，不是偏移量不够** —— `text()` 默认 `textAlign='center'`，锚点是**墨盒中心**；旧实现把中心锚在「入口中心 + 36px」，于是近端 = `36 − 字宽/2`，**字数越多越往里缩**。

| 名称 | 字数 | 字宽 | 旧近端 | 后果 | 新近端 |
|---|---|---|---|---|---|
| 打飞机 | 3 | 32.7 | **19.7px** | 已落在 r24 圆环**内部**，压住描边 | **32px** |
| 重新游戏 | 4 | 43.6 | **14.2px** | 压到 24px 图标上 | **32px** |
| 导弹指挥部 | 5 | 54.5 | **8.7px** | 几乎盖住整个图标 | **32px** |

这解释了为什么"把偏移量调大一点"治标不治本——3 字刚好的值，5 字一定糊。

**修复**：锚点从「中心」改为「近端」，近端恒在 `ENTRY_R 24 + LABEL_GAP 8 = 32`，再背向入口向外生长。**旧常量 `LABEL_OFFSET` 已删除**，新增 `ENTRY_R` / `LABEL_GAP` / `LABEL_SIZE` / `LABEL_WEIGHT` / `LABEL_H` 一组，任何写死 36 的代码都会拿到 `undefined`。

配套新增 `textWidth(ctx, str, opt)`：`measureText` 不在 AIUI 确认 API 范围内，真机可能返回 0 / undefined，故**与字宽估算取大值**（CJK ≈ 0.99 × size、拉丁 ≈ 0.52 × size）。取大非取小，保证底框永不裁切。

> **画布此前一直是对的**：画布上标签本就是 `textAlignHorizontal: LEFT`（近端贴环），是**代码侧居中**导致真机与画布观感不符。本次是让代码追上画布。

## 附 · 变更记录 v1.44（音效规格修正 · 真机无声）

**现象**：v1.43 出包后真机实测**完全没有任何音效**。

**逐段排查（先排除，再定位）**：包内 `assets/sfx/` 8 个 wav 确实随包；
`settings.sfxOn` 默认 `true`；玩法链路 `SFX_OF` / 框架页 `_play()` 均正常 ⇒
既不是"文件没进包"，也不是"开关关着"，只剩**音频规格**与**拿构造器**两处。

**两处修正**：

1. **音频规格 8kHz/8bit → 16kHz/16bit**（合计 65KB，整包 +13%）。
   8-bit PCM 是压缩音频时代前的遗留格式，**多数嵌入式 / 移动端解码器已不再支持**，
   这是"文件在、链路通，但一声不出"最可能的主因。
   `tools/gen-sfx.py` 改用 `array('h')` 写 16-bit 样本，新增 8ms 淡出，
   GAIN 0.82（留 1.8dB 余量防削波）。
   ⚠ 教训：**怀疑"没声音"时优先怀疑位深 / 采样率，不要一上来怀疑代码链路。**
2. **构造器获取 → 四级探测**（v1.43 只认 `globalThis.Sound` 一种）：
   注入值 → `globalThis.Sound` → `globalThis.audio.Sound`（命名空间形式）
   → 运行时 `require('audio').Sound`（**不是 import**，失败可 catch，无解析期崩溃面）。
   另增**路径候选** `/assets/sfx/` → `assets/sfx/` → `./assets/sfx/`
   （官方两种示例都给过，不同运行时基准目录不同）。

**可见变化**：主页进选择态 6s 内诊断行显示 `| sfx 8/8x3`
（就绪数/总数 × 已播放次数）或 `| sfx NO-CTOR`（四级探测全失败）。

**验证**：`harness-sfx.mjs` 42 → **58 项**（新增 I 组：四级探测、路径回退、
probe 只构造不发声、brief 格式；G2 改判 16kHz/16bit、G3 阈值 <128KB、
